# Proposal

## Why

Типичный случай из кафе: часть позиций человека не касается, что-то он заказал себе, что-то делится на несколько человек (кальян на троих, чай на всех). Сейчас «Разделить счёт» требует ввести итог и разложить его поровну, долями или суммами. По позициям это приходится считать в уме, а при некруглых суммах это неудобно. Нужно и «сколько с меня, если платил другой», и «сколько должен каждый, если платил я». Деление по позициям чека было явно отложено в change `add-split-bill`.

## What Changes

- В форме «Разделить счёт» появляется переключатель режима «Одной суммой / По чеку» в начале первого шага. «Одной суммой» — нынешняя форма без изменений.
- В режиме «По чеку»:
  - поля суммы нет, итог — сумма внесённых позиций;
  - второй шаг — позиции вместо «Как делим». У позиции есть название, цена за строку, отметки участников, которые её делят, и счётчик «+ ещё N» для людей без имени.
- Плательщик в режиме «По чеку» только один: пользователь или любой участник. Режима «Несколько» нет.
- Доля каждого считается точно по всем позициям. Неделимые копейки раздаются один раз на весь чек, сумма долей равна итогу.
- Дальше работает существующий счёт: «Кто кому переводит», подписи участников, сводка последствий, долги с «Я», статус, экран счёта, изменение и удаление. Доли людей без имени долгов не создают, под итогом это поясняется.
- В меню «+» три пункта:
  - «Новый долг»;
  - «Разделить счёт» с новой подписью «Одна сумма на компанию: такси, дача»;
  - «Разделить по чеку» с подписью «По позициям: кто что ел и пил». Пункт открывает ту же форму сразу в режиме «По чеку».
- Экран счёта по чеку дополнительно показывает позиции. На главной и на карточке долга такой счёт описывается как «<сумма> по чеку».
- Формат резервной копии получает версию 3: у счёта есть список позиций. Копии версий 1 и 2 импортируются как раньше, их счета остаются без позиций.

### Вне скоупа

- Несколько плательщиков в режиме «По чеку».
- Реальный итог чека и «остальное в чеке»: итог всегда равен сумме внесённых позиций.
- Сервисный сбор, чаевые, скидки.
- Количество в позиции («×3»): цена вводится за всю строку.
- Неравные доли внутри позиции: позиция делится между отмеченными поровну.
- Распознавание чека (фото, QR, API ФНС): требует сети и противоречит offline-first.
- Пункт «Разделить по чеку» на пустой главной и в ярлыках установленного приложения.

## Capabilities

### New Capabilities

Нет: деление по чеку — способ деления счёта, оно живёт в `bills`.

### Modified Capabilities

- `bills`:
  - новые требования — режим «По чеку» в форме, позиции чека, доли по позициям, проверка позиций, позиции на экране счёта;
  - уточняются создание счёта, один плательщик, проверка перед сохранением, экран счёта и изменение после погашений.
- `dashboard`: в меню «+» три пункта, у «Разделить счёт» новая подпись; в строке секции «Счета» у счёта по чеку — «<сумма> по чеку».
- `debts`: на карточке долга из счёта по чеку — метка «Из счёта · <сумма> по чеку».
- `data-management`: импорт принимает копию версии 3 с позициями чека и копии прежних форматов без позиций.

## Impact

- **Данные:** `PersistedBill` получает поле `items` и способ деления `"items"`.
  - Версия IndexedDB не меняется: стор `bills` хранит объекты без схемы полей.
  - У старых счетов отсутствующее `items` нормализуется в `[]` при `hydrate` и экспорте.
  - Резервная копия — версия 3. Копии версий 1 и 2 читаются. Копию версии 3 прежние версии приложения отклонят как неверный формат и не прочитают её ошибочно.
- **Код:**
  - расчёт счёта в `entities/debt/model/bill`;
  - форма `features/create-bill` (режим, шаг позиций);
  - маршрут создания счёта с режимом;
  - экран счёта, строка счёта и метка на карточке долга;
  - меню «+»;
  - `storage/backup.ts`.
- **Документация:** `docs/domain.md` (позиция чека, способ деления «По чеку»), `docs/architecture.md`, `CHANGELOG.md`.
- Зависимостей и сетевых запросов не добавляется.
