# Proposal

## Why

Типичный случай из кафе: заплатил кто-то другой, а пользователю нужно понять, сколько с него. Часть позиций его не касается, что-то он заказал себе, что-то делится на несколько человек (кальян на троих, чай на пятерых). Сейчас «Разделить счёт» требует ввести итог и разложить его на всех участников по именам — для «сколько с меня» это слишком долго, а считать доли позиций в уме неудобно, когда суммы некруглые. Деление по позициям чека было явно отложено в change `add-split-bill`.

## What Changes

- Новый пункт меню «+» — «Моя часть чека» с подписью «Кальян на троих, бургер мой — сколько с меня». Он открывает отдельный экран из одного шага: «За что», валюта, «Кто заплатил» (контакт) и список позиций «название, цена, на скольких». Позиции, которые пользователя не касаются, не вносятся; пользователь входит в каждую внесённую позицию.
- Моя часть считается точно: сумма «цена / на скольких» по позициям округляется до копейки один раз. Итог счёта равен сумме внесённых позиций, отдельного поля итога нет.
- Сохранение создаёт обычный счёт со способом деления «По чеку» и одним долгом «Я должен <плательщик>» на мою часть. Статус, погашение, удаление и связь долга со счётом работают по правилам счёта.
- Экран счёта для счёта по чеку показывает позиции и мою часть вместо деления между участниками. «Изменить» открывает форму чека; после погашений меняется только «За что».
- Подпись пункта «Разделить счёт» в меню уточняется: «Одна сумма на компанию: такси, дача». На экране чека под «Кто заплатил» есть подсказка со ссылкой для случая, когда платил сам пользователь.
- На главной и на карточке долга счёт по чеку описывается как «<сумма> по чеку» вместо «<сумма> на <N>».
- Формат резервной копии получает версию 3: у счёта есть список позиций. Копии версий 1 и 2 импортируются как раньше, их счета остаются без позиций.

### Вне скоупа

- Имена в позициях («кальян: я, Анна и ещё один») и переводы каждому участнику — этап 2. Модель позиции сразу хранит отмеченных участников и число людей без имени, чтобы этап 2 обошёлся без миграции.
- Чек, который оплатил сам пользователь: подсказка ведёт в «Разделить счёт».
- Несколько плательщиков.
- Реальный итог чека и «остальное в чеке».
- Сервисный сбор, чаевые, скидки.
- Количество в позиции («×3») — цена позиции вводится за всю строку.
- Распознавание чека (фото, QR, API ФНС): требует сети и противоречит offline-first.
- Пункт «Моя часть чека» на пустой главной и в ярлыках установленного приложения.

## Capabilities

### New Capabilities

Нет: счёт по чеку — разновидность счёта и живёт в `bills`.

### Modified Capabilities

- `bills`: новые требования к форме «Моя часть чека», расчёту моей части, долгу из чека, экрану и изменению счёта по чеку; экран счёта и изменение счёта уточняются для способа деления «По чеку».
- `dashboard`: в меню «+» три пункта, у «Разделить счёт» новая подпись; в строке секции «Счета» у счёта по чеку — «<сумма> по чеку».
- `debts`: на карточке долга из счёта по чеку — метка «Из счёта · <сумма> по чеку».
- `data-management`: импорт принимает копию версии 3 с позициями чека и копии прежних форматов без позиций.

## Impact

- Данные: `PersistedBill` получает поле `items` и способ деления `"items"`. Версия IndexedDB не меняется: стор `bills` хранит объекты, поэтому новые индексы не нужны; у старых счетов отсутствующее `items` нормализуется в `[]` при `hydrate` и экспорте. Резервная копия — версия 3; копии версий 1 и 2 читаются, копию версии 3 прежние версии приложения отклонят как неверный формат и не прочитают её ошибочно.
- Код: расчёт счёта в `entities/debt/model/bill`, новая фича формы чека, маршрут и страница создания, страница изменения счёта, экран счёта, строка счёта и метка на карточке долга, меню «+», `storage/backup.ts`.
- Документация: `docs/domain.md` (позиция чека, способ деления «По чеку»), `docs/architecture.md` (новый слайс и маршрут), `CHANGELOG.md`.
- Зависимостей и сетевых запросов не добавляется.
