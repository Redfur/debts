# Design

## Context

Мотивация и объём — в `proposal.md`; наблюдаемое поведение — в пяти delta-specs этого изменения.

Сейчас `CurrencyCode` в `shared/lib/storage/schema.ts` — union из четырёх кодов. `shared/config/currencies.ts` содержит четыре справочника и фиксированный круг. `fetchExchangeRates` получает USD-ответ существующего API, но отбирает только четыре курса. `CurrencyPicker` — общий управляемый диалог, который используют формы через `AmountField` и напрямую в счёте и настройках.

`shared/lib/currency-preference.ts` хранит единственное значение `debts.displayCurrency`; и настройка, и `HomeTotalsCards` меняют его. Подписчики уже используют текущую валюту для сводок на главной и в контактах. Сброс client-side настроек централизован. Валидатор черновиков отдельно перечисляет четыре валюты. Импорт бэкапа проверяет структуру, но не имеет отдельного whitelist валют: расширение каталога не требует переписывать весь импорт.

## Goals / Non-Goals

**Goals:** единый типизированный каталог, общие чистые правила формирования наборов, независимые предпочтение и отображение, совместимость локальных данных без новой версии IndexedDB.

**Non-Goals:** перенос предметной логики в `shared`, новая инфраструктура состояния или тестирования, автоматические сетевые запросы за метаданными при открытии списка, изменение денежной арифметики. Новые языки не включаются; для них предусматривается явное соответствие локали валюте.

## Decisions

### 1. Полный офлайн-каталог вместо зависимости выбора от сети

В `shared/config` хранить один каталог с кодом, русским названием, короткой подписью и обозначением. Тип кода выводить из набора ключей каталога; `storage/schema.ts` использует и реэкспортирует этот тип. Каталог не должен зависеть от storage, чтобы не создавать цикл импортов. Дублирующиеся списки символов и названий заменить доступом к единому источнику в пределах затронутых вызовов.

Каталог формируется по полному ответу `/currencies.json` используемого `fawazahmed0/currency-api`, сверяется с действующими обычными валютами ISO 4217 и поставляется с приложением. Зафиксировать источник и дату сверки рядом с данными. Включать обычные валюты стран, территорий и валютных союзов, а не все трёхбуквенные коды: ISO также содержит металлы, фонды и расчётные единицы. Не использовать только `Intl.supportedValuesOf('currency')` как классификатор — он не задаёт нужную продуктовую границу. Проверка полноты каталога против снимка API при реализации не является runtime-запросом приложения.

Полностью динамический каталог потребовал бы классификатора и русских подписей для новых кодов, отдельного хранения и правил первого офлайн-запуска. Это избыточно для текущего объёма. Новые государственные валюты, появившиеся в источнике после выпуска приложения, добавляются обновлением каталога; временное отсутствие курса не удаляет валюту из выбора.

Для денежных подписей сохранить существующие символы четырёх валют; остальным задать подходящее короткое обозначение, при отсутствии — код. В списке выбора код показывается всегда, чтобы различать одинаковые символы. Не переходить на число дробных знаков из `Intl.NumberFormat` для конкретной валюты: текущая арифметика долгов и деления счёта остаётся с точностью 0,01.

### 2. Отдельные локальные предпочтения

Оставить `debts.displayCurrency` текущей валютой, добавить `debts.preferredDisplayCurrency` для предпочитаемой. Модуль `shared/lib/currency-preference.ts` предоставляет чтение и подписки на оба значения. `setDisplayCurrency` меняет только текущую, отдельное действие выбора предпочитаемой меняет обе. Событие обновления должно доставлять согласованный снимок после изменения обеих настроек, чтобы UI не видел промежуточное состояние.

При отсутствии настроек предпочитаемая равна валюте языка, текущая — предпочитаемой. Недопустимые значения не принимаются. Ошибка записи localStorage не должна останавливать интерфейс; действовать в соответствии с существующим поведением настроек в памяти. Оба ключа входят в `CLIENT_STORAGE_KEYS`, общий сброс и уведомление подписчиков обновляют оба значения. Настройки не добавляются в экспорт доменных данных.

В `features/set-display-currency` сохранить существующий слайс и показывать две строки с отдельными выборами. Подсказки объясняют результат: предпочитаемая «Всегда в быстром выборе. При выборе переключает итоги», текущая «В ней сейчас показаны итоги. Меняется нажатием на сумму на главной». Все сводки продолжают читать текущую валюту, а не предпочитаемую.

### 3. Общие правила наборов без нарушения FSD

В `entities/debt/model` добавить вычисление уникальных валют всех сохранённых долгов и только активных долгов; связанные со счётом долги участвуют как обычные. Критерий открытого долга тот же, что в существующих агрегатах итогов. Не учитывать валюту счёта отдельно, если он не создал долг пользователя, и не учитывать черновики.

В `shared` чистые функции получают готовые коды, валюту локали и предпочитаемую; выполняют упорядочивание и устранение повторов. Определение валюты локали — явная конфигурация рядом с каталогом: сейчас `ru`/`ru-RU` → RUB, для неподдерживаемой локали — соответствие фактически выбранного fallback-языка. Подключение будущей локали обязано задать её валюту (например `zh-CN` → CNY); геолокация и язык ОС не участвуют.

Формулы:

```text
pickerTop = unique([locale, preferred, USD, ...sort(allDebtCurrencies)])
homeCycle = unique([locale, preferred, USD, ...sort(activeDebtCurrencies)])
```

Сортировка использованных валют — по коду. Остальной каталог сортируется по русскому названию и коду. Текущая валюта сама по себе не добавляется ни в один набор. Если она отсутствует в круге, следующий клик выбирает первый элемент; изменение долгов не переключает её автоматически.

Хук в `entities/debt` собирает данные из стора и preferences для потребителей через публичный API. Формы и feature настроек передают верхние коды в `CurrencyPicker`/`AmountField` параметрами. Общие UI-компоненты остаются в `shared` и не импортируют entities. В `widgets/home-screen` круг вычисляется один раз и передаётся карточкам; обе используют одинаковую последовательность независимо от направления долга.

### 4. Интерфейс полного выбора

Расширить существующий `CurrencyPicker`, сохранив шторку на мобильном и диалог на десктопе. Переиспользовать `SearchField`, существующие radio-компоненты shadcn и токены; не добавлять библиотеку combobox или виртуализации для такого размера списка. Область списка прокручивается в пределах окна, заголовок и поиск остаются доступными при экранной клавиатуре.

Пустой запрос показывает две группы без дублей. Непустой запрос фильтрует обе по коду и русскому названию, скрывая пустые заголовки; результат не ранжируется иначе. При закрытии запрос очищается. Выбор, включая повторный выбор уже отмеченной валюты, закрывает окно. Проверить клавиатуру, озвучивание названий/кодов, галочку выбранного и возврат фокуса к триггеру.

### 5. Курсы и персистентность

`shared/lib/exchange-rate/fetch-rates.ts` продолжает получать один USD-ответ с существующим зеркалом, но сохраняет конечные положительные курсы всех валют каталога. USD нормализуется к 1; отсутствующие/недопустимые курсы не записываются как ноль или фиктивное значение. Тип карты — частичный набор кодов (`Partial<Record<CurrencyCode, number>>`), поскольку старый кэш и неполные ответы допустимы. `convertAmount` отвергает неположительный курс как для исходной, так и для целевой валюты.

Старый кэш остаётся пригодным для имеющихся в нём валют. Новые курсы появятся при очередном обычном либо ручном обновлении: расширение каталога не обходит существующее ограничение фоновых запросов. До этого доступны исходные суммы и создание долгов, а конвертация без нужного курса недоступна по правилам `dashboard`. Не менять общую обработку ошибок API или расписание запросов за пределами необходимого.

Хранимые долги, счета и черновики уже используют строки кодов; `rates` — объект. Поэтому не нужны новое хранилище, версия IndexedDB, версия бэкапа или версия черновика. Валидатор `entities/debt/model/creation-drafts/validate.ts` должен принимать единый каталог, иначе формы в THB перестанут восстанавливаться. В импорте не выполнять попутное ужесточение всей проверки доменных данных; проверить round-trip новых валют и чтение форматов 1–3.

## Risks / Trade-offs

- Состав валют источника меняется после выпуска → каталог имеет источник и дату сверки; новые коды добавляются обновлением приложения, а сетевой сбой не сокращает доступный список.
- Старый кэш не содержит THB/KZT → неполный кэш допустим, исходные суммы доступны, ручное обновление получает новые курсы без принудительного сброса старого кэша.
- После погашения валюта исчезает из круга → сохранять текущую до клика; следующее нажатие начинает с первой валюты, без скрытого изменения настройки.
- Язык не определяет валюту однозначно → соответствие задаётся явно для локали продукта, без попытки угадывать регион пользователя.
- Откат приложения не знает новые коды, хотя формат бэкапа остался прежним → поддерживается чтение старых данных новой версией; обратную совместимость новых валют со старым кодом не обещать.

## Migration Plan

1. Выпустить каталог, новые настройки и их потребителей одним изменением. Перед первым переключением инициализировать предпочитаемую: валидное новое значение → прежняя текущая → валюта языка. Текущая: валидное сохранённое значение → предпочитаемая.
2. Записать новую предпочитаемую один раз до изменения текущей. Если запись недоступна, запомнить мигрированное значение в памяти сеанса, чтобы клик не стал новым источником предпочитаемой. Повторная инициализация не перезаписывает валидные новые значения.
3. Сбросить обе валюты к валюте языка через существующий общий сброс; долги и черновики не трогать. Удаление только доменных данных сохраняет оба предпочтения.
4. Проверить миграцию с EUR, чистый профиль, повторный запуск после переключения и сброс. Существующие записи и кэш не переписывать.
5. Откат возможен без структурной миграции БД, но для профиля с новыми валютами безопаснее использовать новую версию приложения. Не удалять новые записи для обеспечения отката и не выполнять автоматическое преобразование валют.
