# Design

## Context

Мотивация и границы — в `proposal.md`, наблюдаемое поведение — в delta `design-system`.

Сейчас `components/ui/dialog.tsx` оформляет Radix Dialog как нижнюю шторку через CSS до 1024 px. `ModalHandle` — декоративный span. `alert-dialog.tsx` использует те же классы и ручку, но Radix AlertDialog запрещает закрытие по фону. Основная спецификация обобщает это поведение неточно; delta различает обычные окна и подтверждения, не добавляя закрытие подтверждений по фону.

В проекте семь потребителей: `CurrencyPicker`, `AddRepaymentDialog`, `EditDebtDialog`, `PayerSheet`, `InstallInstructionsSheet`, `ConfirmActionModal`, `ImportBackupConfirm`. Среди них есть управляемые окна на useState и предметные модалки NiceModal. Выбор валюты может открываться внутри редактирования долга. Существуют Radix Select/Popover и обход ошибки с pointer-events вложенных порталов.

Клавиатура сейчас учитывается через `useKeyboardInset` в DialogContent; тот же хук нужен полноэкранным формам. В NiceModal обработчики ожидают `modal.hide()` перед `remove()`, но отсутствует вызов `resolveHide`; это видно и в комментарии обхода в EditDebtDialog. При внедрении Drawer нужно завершать этот жизненный цикл по фактическому завершению закрытия.

## Goals / Non-Goals

**Goals:** единый адаптивный контракт окон, библиотечная обработка жестов и согласованный жизненный цикл; локальная интеграция в существующие UI и FSD без изменения модели данных.

**Non-Goals:** собственный движок физики/распознавания свайпов, общий переход UI-kit на Base UI, переписывание NiceModal, новая система навигации или черновиков, промежуточные высоты и эффект масштабирования всей страницы за шторкой.

## Decisions

### 1. Base UI Drawer в отдельном компоненте UI-kit

Добавить `@base-ui/react` как runtime-зависимость при реализации, зафиксировать установленную совместимую версию lockfile. За основу `components/ui/drawer.tsx` взять вариант shadcn для Base UI, сохранив токены приложения, отступы, радиусы и safe area. Не менять `components.json` с `radix-nova` и не запускать массовую регенерацию компонентов: текущий registry по умолчанию относится к Radix, а нужен только вариант Drawer на Base UI.

Источники, проверенные при проектировании:
- [shadcn Base Drawer](https://ui.shadcn.com/docs/components/base/drawer): библиотечный Drawer, адаптивное сочетание с Dialog, прокручиваемый контент и особенности iOS overlay.
- [Base UI Drawer](https://base-ui.com/react/components/drawer): управляемое состояние, вложенность, `swipeDirection`, `data-base-ui-swipe-ignore`, `VirtualKeyboardProvider`, отмена закрытия через details.cancel и `onOpenChangeComplete`.

Альтернативы: дописать свайп в текущий Radix Dialog — придётся поддерживать физику, scroll arbitration и клавиатуру самостоятельно; перевести весь UI на Base UI — значительно расширяет задачу. Выбранная зависимость применяется только к мобильным модальным окнам. Библиотечные возможности не означают проверенную совместимость с нашими Radix-порталами: это отдельные интеграционные сценарии, а не основание исключать их из проверки.

### 2. Адаптивный слой с одним активным движком

В `components/ui` создать небольшой общий слой для режима, состояния открытия, `dismissible` и уведомления о завершении закрытия. Существующие `dialog.tsx` и `alert-dialog.tsx` становятся адаптивными оболочками: на мобильном рендерятся согласованные части Base Drawer, на десктопе — прежние Radix-примитивы. В одном открытом окне не монтировать одновременно обе реализации и два focus trap.

Снаружи сохранить используемую композицию `Root / Trigger / Content / Title / Description / Close` и boolean `onOpenChange`. Не пытаться поддержать весь набор несовместимых props двух библиотек: адаптировать используемые в проекте props и `asChild` к Base UI `render` локально, с явной типизацией, без `any`. Все части конкретного окна получают один выбранный backend через контекст; нельзя оставить Radix Title/Close внутри Base Popup.

Режим выбирается по ширине `< 1024 px`, не по user-agent или наличию touch. Предлагаемый технический default: зафиксировать backend на время открытия до завершения закрытия; новое открытие использует актуальную ширину. Это исключает remount и потерю фокуса при повороте устройства. Оформление открытого окна соответствует зафиксированному backend, а не переключается наполовину CSS-медиазапросом.

Области ответственности FSD:
- `components/ui`: Drawer, адаптивные Dialog/AlertDialog, focus/portal/scroll-lock и анимации без предметных действий.
- `shared/ui`: общий confirm и выбор валюты используют UI-контракт; confirm владеет выполнением переданного действия. Переиспользуемый небольшой хук интеграции NiceModal, если нужен, размещается в `shared/lib` и используется всеми предметными модалками.
- `features/add-repayment`, `edit-debt`, `import-backup`, `create-bill`, `install-app`: передают состояние выполнения и подключают завершение закрытия, не реализуют собственные свайпы.
- `widgets`, `pages`, `entities`: финансовые операции, страницы и данные не меняются; `app` затрагивается только если выбранной композиции Drawer требуется общий provider.

### 3. Жесты, прокрутка и компоновка

Один полностью открытый уровень высоты; использовать стандартные критерии расстояния/скорости библиотеки без собственной настройки пользователя. Ручка и свободная часть заголовка — область перетаскивания с зоной не меньше 44 px по высоте. Интерактивные потомки заголовка, поля, выделение текста и кнопки исключаются из drag-поверхности через библиотечные механизмы.

Контейнер списка/формы — отдельный flex-item с `min-h-0` и `overflow-y-auto`; ручка, заголовок и необходимые действия не должны уезжать со списком. У CurrencyPicker сохранить закреплённый поиск и внутреннюю прокрутку длинного каталога. Не ставить `touch-action: none` на всё содержимое и не блокировать нативный ввод/прокрутку глобальным preventDefault.

Для движения из содержимого использовать scroll arbitration Drawer. Согласованное правило: если начало жеста пришлось на список с `scrollTop > 0`, всё движение остаётся прокруткой, даже если достигнут верх. При необходимости локальный адаптер фиксирует начальную scroll-позицию и исключает это движение из свайпа библиотечным API; физику движения и анимацию продолжает выполнять Drawer. Ручка работает независимо от scrollTop. Завершение свайпа не должно вызывать click по пункту списка или странице под исчезнувшим окном.

Для нижней шторки применять `VirtualKeyboardProvider` Base UI как единственный механизм клавиатурного сдвига. Не добавлять поверх него прежний `--keyboard-inset` из DialogContent: двойная компенсация поднимет окно слишком высоко. `useKeyboardInset` сохранить для полноэкранных страниц. Учитывать требуемое библиотекой позиционирование body для iOS overlay, не вводя масштабирование страницы. Уменьшение движения учитывать стилями открытия, возврата и закрытия; непосредственное следование за пальцем сохраняет смысл жеста.

### 4. Вложенность и фокус

Дочерний Drawer должен оставаться логическим потомком родительского Root, даже если DOM вынесен в portal. Для NiceModal-модалок с независимыми корнями сохранять корректный порядок верхних слоёв без двойной обработки Escape. Не заменять библиотечное управление слоями самостоятельной глобальной системой окон.

Проверить `EditDebtDialog → CurrencyPicker`, дочерние Radix Select/Popover и закрытие верхнего слоя. При закрытии дочернего окна родительский DOM и состояние формы остаются смонтированными. Scroll-lock страницы снимается только после последнего окна. Начальный фокус и возврат задаются явно, в том числе когда NiceModal не имеет собственного Trigger; если инициатор удалён после успешной операции, выбрать ближайший существующий логический элемент вместо фокуса на скрытом узле.

Сохранить именование и роль: обычные окна — dialog, подтверждения — alertdialog с начальным фокусом на безопасном действии. Не считать role единственным отличием: блокировка клика по фону и выполнение действия задаются отдельно. Если окно не имеет явной кнопки закрытия (в частности выбор валюты/плательщика), добавить доступную кнопку «Закрыть»; не дублировать существующие «Отмена» и крестик инструкции установки.

### 5. Политика отмены и выполнение операций

Для обычного окна доступно закрытие по фону, Escape, кнопкой или свайпом. Для подтверждения свайп/кнопка отмены/Escape разрешены до запуска действия, клик по фону всегда отклоняется. Жест не вызывает `onConfirm`, submit, onPick или изменение валюты; уже совершённый выбор не откатывается. Полноэкранные черновики не удаляются при закрытии вспомогательного выбора.

Общий `dismissible` блокирует все пользовательские пути закрытия во время операции на обоих backend. В Base UI отменять запрос закрытия через `details.cancel()`; у Radix предотвращать Escape/outside и отклонять пользовательские onOpenChange, отключать кнопки отмены/крестик. Библиотечный или локальный запрет swipe должен не позволять утащить busy-окно за пределы экрана, даже если затем закрытие отклонится. Программное закрытие после завершения операции остаётся доступным.

В ConfirmActionModal добавить локальное состояние выполнения и синхронную защиту повторного запуска; обычный AlertDialogAction не должен автоматически закрывать окно до окончания `onConfirm`. В ImportBackupConfirm использовать имеющийся busy для всех путей закрытия, а в погашении/редактировании — существующий pending. После завершения разблокировать окно в finally; сохранить текущую обработку ошибок вызывающего сценария, не добавлять молчаливый catch или новую универсальную политику ошибок. Успешное действие закрывает окно после завершения записи; импорт/сброс могут выполнить предусмотренную перезагрузку.

### 6. Завершение закрытия и NiceModal

Жест и кнопки сначала меняют видимость через один путь закрытия; предметное действие при отмене не выполняется. По окончании выходной анимации вызвать `modal.resolveHide()` и `modal.remove()` ровно один раз. У Base UI использовать `onOpenChangeComplete(false)`, у Radix — завершение его presence/exit, учитывая reduced-motion и отсутствие анимации. Не использовать таймер, привязанный к фиксированным 200 ms. Не ждать hide до того места, которое должно resolveHide: это оставит promise незавершённым.

Не удалять родительскую NiceModal при закрытии вложенного CurrencyPicker. Сохранить используемые результаты публичных helper-ов; не переопределять return-value всех подтверждений в рамках миграции. Специальный обход перехода к счёту в EditDebtDialog пересмотреть только в части согласования с завершением hide, без изменения маршрутизации.

## Risks / Trade-offs

- Base UI Drawer и Radix Select/Popover по-разному управляют порталами и фокусом → проверить вложенный выбор до переноса всех окон; адаптировать границы слоёв локально, не мигрировать весь UI-kit.
- Сдвиг над клавиатурой применяется дважды → единый владелец клавиатурной геометрии у мобильного Drawer, отдельная проверка Safari/iOS и Chrome/Android.
- Подтверждение автоматически закрывается раньше завершения записи → preventDefault на action, единый busy/dismissible, проверка с управляемой задержкой операции и повторными нажатиями.
- Незавершённый hide или мгновенный remove ломает анимацию/повторное открытие → общий lifecycle callback, resolveHide и remove после закрытия, сценарии многократного открытия и reduced-motion.
- Поворот устройства размонтирует активный backend → фиксировать backend до закрытия; проверить сохранность родительских полей и верхнего слоя при изменении ширины.
- Эмуляция viewport не воспроизводит полностью системную клавиатуру и touch-scroll → реальные iOS Safari и Android Chrome проверяются отдельным шагом; отсутствие устройства фиксируется как невыполненная проверка, а не заменяется заявлением об успехе.

## Migration Plan

1. Добавить зависимость и UI-компонент Drawer с локальными стилями и адаптивным контрактом. Не менять данные, версии хранилищ или другие компоненты shadcn.
2. Подключить общий слой сначала к CurrencyPicker и вложенному редактированию; проверить жесты, прокрутку и focus/portal-взаимодействия. Затем перевести оставшихся перечисленных потребителей и подтверждения с busy-защитой.
3. Довести lifecycle NiceModal и регрессионные проверки всех способов закрытия и повторного открытия. Обновить документацию и пользовательский changelog в том же изменении, что код.
4. Проверить production PWA без сети и мобильные устройства, выполнить обязательные команды проекта. Архивировать только после отдельного разрешения пользователя.
5. Откат — отмена коммита реализации с возвратом прежнего UI и зависимости/lockfile; миграции финансовых данных не нужны. Артефакты `expand-fiat-currencies` остаются независимыми.
