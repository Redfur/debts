# Design

## Context

Мотивация и границы — в [proposal.md](./proposal.md). Изменение сквозное: переводы, денежные поля, форматтеры, настройки и сборка PWA используют общие предпочтения.

Проверенное состояние:

- `shared/lib/i18n.ts` фиксирует `lng` и fallback в `ru`; 23 файла переводов колоцированы со слайсами и подключаются через `injectTranslation`.
- `format-amount.ts` создаёт русский форматтер на уровне модуля; `format-date.ts` использует русские месяцы и date-fns `ru`. Дата релиза отдельно форматируется в `ChangelogScreen`.
- `AmountInput` держит нормализованную строку с точкой и DOM-значение через `defaultValue`; общий `sanitize` для любых изменений молча удаляет символы и обрезает дробь. Такой обработчик не годится для строгой вставки или смешения десятичного разделителя с автоматически добавленной группировкой.
- Деньги хранятся числами, поля черновиков — нормализованными строками. `Number(amount)` используется после нормализации; локализованную строку нельзя передавать в предметные расчёты.
- Валютный каталог содержит русские `label` и `shortLabel`; сортировка валют и контактов фиксирована на `ru`. Валюта языка пока только RUB. Предпочтения валют инициализируются лениво и сохраняют существующий выбор.
- Общий сброс удаляет `CLIENT_STORAGE_KEYS`, переинициализирует тему и уведомляет валютные предпочтения. Новый язык нужно разрешать до сброса валют, иначе возможен неверный RUB/USD.
- `vite.config.ts` создаёт единственный русский `site.webmanifest`, сохраняет стабильный `id: base`; `.webmanifest` не входит в текущий `globPatterns` офлайн-кеша.
- Основные спецификации ещё не включают завершённый `expand-fiat-currencies`. Его delta — основание для `specs/currencies/spec.md` этого change; необходим перенос в основные спецификации до реализации/синхронизации настоящего change. Чужой change здесь не изменяется.

## Goals / Non-Goals

**Goals:** одна согласованная пара эффективных значений языка и формата, мгновенное обновление потребителей, сохранение исходного ввода и денежных значений, офлайн-доступность обоих языков.

**Non-Goals:** новый общий framework настроек, подключение детектора языка как зависимости, реорганизация всех переводов, региональные версии английского, изменение денежной арифметики или механизмов установки.

## Decisions

### 1. Предпочтения и эффективные значения

В `shared/lib` создать небольшой модуль предпочтений локализации с чистыми функциями разрешения языка/формата и подпиской через существующий в проекте подход `useSyncExternalStore`. Хранить режим языка `system | ru | en` и формат `language | space-comma | space-dot | comma-dot | dot-comma` в отдельных ключах `CLIENT_STORAGE_KEYS`. Валидировать значения при чтении; неизвестное значение означает стандартный режим. При недоступном localStorage сохранять работоспособность в памяти сеанса, как у валютных предпочтений.

В системном режиме обходить `navigator.languages` по порядку, сопоставляя базовый язык `ru`/`en` без учёта регистра; при отсутствии списка использовать `navigator.language`, при отсутствии поддерживаемого языка — en. Слушать `languagechange`; ручное предпочтение оно не меняет. Не обращаться к геолокации и не выводить язык из формата чисел.

Эффективный язык определить при инициализации i18n до чтения валютных предпочтений и первого отображения UI. Для i18next задать поддерживаемые языки ru/en и fallback en. Изменение языка передаётся в существующий i18n; изменение только числового формата публикует отдельный снимок, а не имитирует событие смены языка. Избежать циклического импорта: чистый модуль предпочтений не импортирует экземпляр i18n.

Альтернатива — browser language detector и общий Zustand-стор всех настроек — добавляет инфраструктуру без необходимости для двух значений.

### 2. Реактивность форматтеров и денежных полей

`shared/lib/format-amount.ts` сохраняет чистую форматирующую часть с явным описателем разделителей. Для UI предоставить небольшой hook/подписку на эффективный формат и обновить потребителей, включая memo-вычисления. Недостаточно читать настройку внутри обычной функции: смена числового формата сама по себе не перерисует компонент с `useTranslation`. Не пересоздавать formatter на каждую сумму; кешировать по четырём форматам.

Форматировать суммы с группировкой по три цифры и до двух дробных знаков без обязательных нулей. Позицию и символ валюты сохранить: после числа через неразрывный пробел. Выбранный формат использовать также в дробных процентах скидок/чаевых; целочисленные счётчики людей и версии не превращать в денежные поля.

`AmountInput` получает эффективный формат и сохраняет внешнее нормализованное `value`. Маска должна обновляться при смене формата даже без изменения `value`, сохраняя незавершённую дробь. Набор обрабатывать как операцию редактирования над нормализованной строкой: знать прежнюю маску, выделение и вставляемые символы; автоматически добавленные разделители разрядов не интерпретировать повторно как десятичные. Допускаются `.` и `,` как ввод десятичного разделителя независимо от маски. Учесть клавиатуру, `beforeinput`/`input`, удаление, выделение, мобильный ввод и курсор. Не ограничиваться заменой `,` на `.` во всей отображаемой строке.

Для `paste` выделить чистый строгий parser: крайние пробелы убрать, группировку проверять, поддерживать число без группировки; в пробельных форматах считать обычный, NBSP и узкий NBSP эквивалентами. Группа после первой — ровно три цифры, дробная часть до двух знаков. Чужой десятичный разделитель не угадывать. Проверять итог вставки с учётом выделенного фрагмента; результат либо целиком применён, либо прежний ввод сохранён. Ошибку передать потребителю и показать существующим `FieldError` с `aria-describedby`; очистить после корректного редактирования. Не использовать тихий `sanitize` для вставки. Не принимать денежный символ или произвольный текст путём удаления символов.

Альтернатива — единый эвристический parser для набора и вставки — противоречит принятой интерпретации `1,234` и может менять сумму в тысячу раз.

### 3. Переводы, даты и валютный каталог

Добавить en рядом с ru в существующих `translations.ts`; проверить соответствие смысловых ключей, интерполяций, plural-форм и `Trans`. Русские формы `_one/_few/_many` не копировать механически: английскому нужны его формы `_one/_other`. Убрать русские фразы из `formatPeopleCount` и других вспомогательных UI-функций. Пользовательские записи не переводить. Общая политика: русские строки других capability описывают русский текст; английский сохраняет тот же смысл и сценарии.

Месяцы и предлоги формируются по эффективному языку, виды дат и правило года сохраняются. Для английского принять единый вид `12 Sep`, `15 October`, `15 October at 12:40`, `12 October 2026, 18:05`, местное 24-часовое время. Это проектное значение по умолчанию без отдельной настройки. Дату релиза форматировать на языке интерфейса с прежним UTC-прочтением календарной даты.

Каталог сохранить офлайн и детерминированным: добавить английские полные и короткие названия к существующим записям, не менять коды, символы и состав валют. Не полагаться на сетевой перевод или различия поддержки `Intl.DisplayNames` между устройствами. Поиск и сортировка работают по выбранному языку; мемоизация включает язык. Сортировка имён контактов тоже получает эффективный язык.

`localeCurrency` расширить en → USD. При смене языка обновлять валюту языка в верхней группе и круге, не сбрасывая уже инициализированные preferred/current. На чистом запуске разрешать язык до их инициализации. Валюта новых форм остаётся RUB; это существующее поведение, обсуждение валюты английского относилось к итогам и верхней группе.

### 4. UI настроек и сброс

В `widgets/settings-screen` заменить заглушку группы языка двумя активными строками «Язык интерфейса» и «Формат чисел». Использовать существующие адаптивные `Dialog` и строки выбора с отмеченным значением, без новых компонентов-зависимостей. Выбор языка имеет три значения; названия «Русский» / `English` всегда написаны на своём языке. Формат имеет пять значений с буквальными примерами, а для автоматического варианта рядом показывается эффективный пример. Закрытие и возврат фокуса следуют текущей дизайн-системе.

В `clearClientStoragePreferences` после удаления ключей последовательно разрешить системный язык и формат, применить i18n/метаданные и затем сбросить обе валюты к валюте этого языка. Обновить подсказку и подтверждение единой кнопки, не добавлять отдельный сброс. «Удалить данные» сохраняет настройки; импорт тоже их не затрагивает. «Очистить всё» удаляет настройки и служебные отметки по прежней схеме.

### 5. Название, HTML и PWA

В `app` подписать метаданные на эффективный язык: `document.title`, `html.lang`, описание и `apple-mobile-web-app-title`. В навигации использовать перевод названия.

На сборке сформировать два статических манифеста из общей конфигурации: сохранить русский `site.webmanifest` и добавить `site.en.webmanifest`. Оба имеют один прежний `id`, одинаковые scope/start_url, маршруты shortcuts и иконки; различаются name/short_name, lang, description и тексты shortcuts. Небольшая локальная сборочная функция/плагин устраняет дублирование и отдаёт оба файла также в dev. На странице оставить одну ссылку manifest, переключаемую по эффективному языку до инициализации установки и затем при смене языка. Не использовать blob/data URL и новые сетевые службы. Проверить base path и относительные URL ресурсов.

Оба манифеста включить в precache. Существующие скриншоты не переводить и не добавлять к офлайн-кешу; это иллюстрации русской версии, пока общие для языков. При смене manifest учитывать уже сохранённый `beforeinstallprompt`: не показывать заведомо устаревший запрос, при необходимости переходить к текущим инструкциям до нового события браузера.

Передача новых метаданных — управляемая часть приложения. Переименование системной иконки уже установленной PWA не гарантируется и не требует переустановки. Основание: [жизненный цикл и обновление манифеста W3C](https://www.w3.org/TR/appmanifest/#updating-the-manifest); требования к фактическому отображению проверять на конкретных браузерах, не подменять отчётом о правильном JSON.

### 6. История релизов и будущий перевод

`CHANGELOG.md` и `virtual:changelog` продолжают поставлять один русский текст. Переводятся только обрамление, заголовки групп и даты. Не заводить пустой английский changelog или runtime-перевод.

Будущее отдельное изменение может хранить переводы записей по стабильным номерам версий, сохранив единый источник номеров/дат и явный русский fallback для непереведённых версий. Это направление зафиксировано для последующего обсуждения, инфраструктура и UI-пометка сейчас не реализуются.

### 7. Расположение по FSD

| Слой | Изменения |
|---|---|
| `shared` | Предпочтения локализации, разрешение языка/формата, i18n, форматтеры и parser, ключи/сброс настроек, названия валют, общие переводы |
| `components/ui` | Маска `AmountInput`, получение формата и callback ошибки без предметной логики |
| `entities/debt` | Переводы сущностей, форматтеры/счётчики людей, зависимость набора валют от языка |
| `features` | Переводы и потребление формата в создании/изменении/погашении/разделении счёта, отображение ошибки вставки, установка |
| `widgets` | Настройки языка/формата, даты и обрамление истории, форматированные суммы и сортировка контактов |
| `app` | Применение языка до первого UI, метаданные и подписки |
| `build`, Vite/HTML | Общая конфигурация локализованных манифестов и их офлайн-кеш |

## Risks / Trade-offs

- Смена формата без перерисовки → явная подписка потребителей; проверка при неизменном языке и на memo-компонентах.
- Смешение вставки и обычного набора → разные обработчики, отдельные проверки неоднозначных значений и редактирования группированной суммы.
- Повреждение черновика маской → хранить нормализованное значение, проверять незавершённую дробь и восстановление после перезапуска на другом языке.
- Неполный английский, скрытый fallback → проверка ключей и интерполяций плюс просмотр основных сценариев/ошибок на обоих языках.
- Ошибка порядка инициализации/сброса валют → чистые проверки системного языка, ручного override и сохранённых валют.
- Несовпадение языка установленного ярлыка → стабильный id, проверка метаданных и реальная проверка установки отдельно; ограничения ОС описать в результатах.
- Ручное ведение английских названий валют → проверка полноты каталога по всем существующим кодам; один каталог без дублирования состава.

## Migration Plan

1. До apply синхронизировать или архивировать завершённый `expand-fiat-currencies` отдельным разрешённым действием. Этот proposal не архивирует другой change.
2. Добавить предпочтения с fallback `system`/`language`, не записывать искусственный ru для пользователей прежней версии. Сохранённые валюты и тема остаются на месте.
3. Выпустить код, переводы и оба манифеста одной сборкой через существующее обновление PWA. Без миграции IndexedDB, изменения версии бэкапа и переписывания черновиков.
4. Проверить обновление с прежней версии, импорт прежних копий, офлайн-запуск и оба языка на не посещённых экранах.
5. При откате старый код игнорирует новые ключи, читает прежние данные и копии; дополнительные ключи не требуют удаления. При последующем возврате новая версия вновь читает выбранные предпочтения.
