# Design

## Context

Мотивация — в proposal.md (Why), требования — в `specs/app-install/spec.md` и `specs/dashboard/spec.md`.

Что есть сейчас:
- `vite.config.ts` подключает `VitePWA` с `registerType: "prompt"`. В манифесте `site.webmanifest`: имя, `display: standalone`, светлые `theme_color`/`background_color` и две иконки 192/512 с назначением только `maskable`. `start_url` и `scope` плагин подставляет сам — это `base` (`/` локально, `VITE_BASE_PATH` на GitHub Pages). `id` не задан, поэтому браузеры считают идентификатором приложения `start_url`.
- `features/pwa-app-update` регистрирует service worker и показывает тост обновления. Вызывается из `src/main.tsx` до рендера React.
- В коде нет обработки `beforeinstallprompt` / `appinstalled`, нет проверки `display-mode` и не используется `navigator.storage`.
- Пустая главная — `widgets/home-screen/ui/HomeOnboarding.tsx`, с кнопками «Добавить первый долг», «Разделить счёт» и «Восстановить из резервной копии». Настройки — `widgets/settings-screen/ui/SettingsScreen.tsx`: группы с `order-*` для мобильной и десктопной раскладки.
- `shared/lib/client-storage-keys.ts` хранит ключи `localStorage`. `clearClientStoragePreferences()` очищает их и вызывается из «Сбросить настройки интерфейса» и «Очистить всё».
- Экспорт копии — `features/export-backup` (`useExportBackup`).
- Автотестов в проекте нет, проверка ручная.

## Goals / Non-Goals

**Goals:**
- Один источник правды о режиме, платформе и доступности системного диалога, который читают главная и настройки.
- Не пропустить `beforeinstallprompt`: браузер присылает его рано, до монтирования React.
- Не задвоить уже установленные копии при изменении манифеста.
- Не раздувать precache скриншотами для диалога установки.

**Non-Goals:**
- Общий механизм «подсказок/онбординга». Плашка установки — частный случай, обобщим, когда появится второй.
- Автотесты: в проекте нет тестовой инфраструктуры, это отдельный пункт roadmap.

## Decisions

### 1. Новый слайс `features/install-app`

Установка и защита данных — действия пользователя с UI и текстами, поэтому это feature, а не `shared`. Структура:

```
features/install-app/
  lib/detect-platform.ts      чистые функции: isStandalone, isIos, isInAppBrowser
  model/install-state.ts      внешний стор: mode, platform, nativePromptAvailable, installedNow;
                              перехват beforeinstallprompt / appinstalled; promptInstall()
  model/use-install-state.ts  useSyncExternalStore поверх стора
  model/storage-persistence.ts  persisted() / persist(), автозапрос в режиме «Установлено»
  model/banner-dismissal.ts   чтение/запись отметки «плашку закрыли»
  model/init-install-app.ts   initInstallApp(): подписки + автозапрос persist
  ui/InstallActionButton.tsx  «Установить» / «Как установить» / «Скопировать ссылку»
  ui/InstallOnboardingCard.tsx
  ui/InstallBanner.tsx
  ui/InstallInstructionsSheet.tsx  NiceModal, шторка «Как установить»
  ui/InstallSettingsRows.tsx  строки «Установка» и «Хранение данных»
  translations.ts, index.ts
```

`initInstallApp()` вызывается в `src/main.tsx` рядом с `initPwaUpdate()`, до `createRoot`. Альтернатива — подписка в `useEffect` компонента — отклонена: событие может прийти до монтирования, и тогда кнопка «Установить» не появится до следующего визита.

Стор хранится как модульное состояние с `subscribe`/`getSnapshot`, без Zustand. Состояние маленькое, не доменное и не персистится; `useDebtStore` для него не подходит. Альтернатива — отдельный Zustand-стор — даёт то же самое с лишней зависимостью в слайсе.

### 2. Определение режима и платформы

Порядок проверки: «Установлено» → «Внутри другого приложения» → «В браузере».
- **Установлено:** `matchMedia("(display-mode: standalone)")`, `fullscreen` или `minimal-ui`, либо `navigator.standalone === true` (iOS). На изменение `display-mode` подписываемся: Chrome на десктопе может переключить окно без перезагрузки.
- **iOS/iPadOS:** `/iPhone|iPad|iPod/` в UA, либо `Macintosh` вместе с `navigator.maxTouchPoints > 1` — iPadOS по умолчанию маскируется под Mac.
- **Встроенный браузер:** регулярка по UA — `Telegram`, `Instagram`, `FBAN|FBAV|FB_IAB`, `VKClient|vkontakte`, `Line/`, Android WebView `; wv)`. Если UA не распознан, режим «В браузере», и пользователь видит общую инструкцию. Это допустимый фолбэк по спеке.
- **Системный диалог:** доступен, пока у нас есть отложенное событие `beforeinstallprompt` (вызываем `preventDefault()` и сохраняем его). После `prompt()` событие одноразовое: сбрасываем его и ждём, не пришлёт ли браузер новое. До тех пор действие — «Как установить».
- **`appinstalled`:** `installedNow = true`, тост «Приложение установлено». Карточка и плашка скрываются, строка «Установка» показывает «Установлено — откройте с экрана «Домой»».

Определение платформы по UA вынесено в `lib/` чистыми функциями, чтобы его можно было проверять без браузера и легко дополнять.

### 3. Где показывать карточку и плашку

- Карточка — внутри `HomeOnboarding` под кнопками. Плашка — в `HomeScreen` над итогами. Оба компонента берутся из публичного API `features/install-app`.
- Ограничение «ширина меньше 1024 px» делаем классом `lg:hidden`, как остальная адаптивная раскладка. `useShellMode` живёт в `app/layout`, и виджеты его импортировать не могут. Отдельный JS-хук для ширины не нужен.
- Условие плашки: `mode !== "installed" && !installedNow && hasData && !dismissed`. `hasData` = есть хотя бы один долг или счёт; считается в фиче через `useDebtStore` из `entities/debt` — feature может импортировать entities. Отдельного события «первая запись» нет. Поэтому плашка один раз появится и у тех, у кого данные уже были до этого изменения. Для пользователей Safari это желательно.

### 4. Сохранение копии из шторки

Шторке нужна кнопка «Сохранить резервную копию», но feature не может импортировать другую feature (`export-backup`). Поэтому `showInstallInstructions({ onSaveBackup })` и `InstallActionButton` принимают колбэк, а виджеты (`home-screen`, `settings-screen`) передают `exportBackup` из `useExportBackup()`. Альтернатива — перенести экспорт в `entities`/`shared` — отклонена: это лишний рефакторинг ради одной кнопки.

Блок переноса показывается, если `hasData && (platform === "ios" || mode === "in-app")`.

### 5. Отметка «плашку закрыли»

Ключ `debts.installBannerDismissed` в `localStorage`. Он **не** входит в `CLIENT_STORAGE_KEYS`: иначе его сбросит «Сбросить настройки интерфейса», а по спеке не должен. В `shared/lib/client-storage-keys.ts` появляется отдельная группа `CLIENT_STATE_KEYS` для служебных отметок. В `shared/lib/clear-client-storage.ts` — `clearAllClientStorage()`: настройки плюс служебные отметки; её вызывает «Очистить всё» в `widgets/settings-screen`. Чтение и запись обёрнуты в `try/catch`, как у темы: в приватном режиме `localStorage` может бросать, и тогда плашка просто считается незакрытой.

### 6. Постоянное хранилище

- Строка «Хранение данных» скрыта, если нет `navigator.storage?.persisted`. В небезопасном контексте и старых браузерах API нет.
- Автозапрос `navigator.storage.persist()` — только в режиме «Установлено», один раз при запуске в `initInstallApp()`, если `persisted()` вернул `false`. Chrome и Safari решают молча, по эвристикам; Firefox показывает свой диалог, но в установленном приложении это ожидаемо. В браузере при запуске не запрашиваем, чтобы Firefox не встречал пользователя чужим диалогом.
- Кнопка «Защитить» вызывает `persist()` по нажатию и показывает тост по результату. Затем строка перечитывает `persisted()`.

### 7. Копирование ссылки

Адрес приложения — `location.origin + import.meta.env.BASE_URL`, а не текущий URL: человек мог открыть внутренний экран. Запись — `navigator.clipboard.writeText`. При ошибке или отсутствии API — тост «Не удалось скопировать ссылку» с адресом в описании, чтобы его можно было выделить вручную.

### 8. Решения из макетов

Макеты — раздел «Установка приложения» холста «Долги — макеты».
- **Карточка и плашка** — один компонент `InstallInvite` в двух видах: нейтральная `card`, знак приложения слева, кнопка `secondary` с иконкой `accent`. Плашка компактнее и с «Закрыть» (иконка, 44 px). Карточка на пустой главной стоит внизу экрана, под центрированным приветствием, а не внутри него.
- **Шторка:** заголовок с кнопкой закрытия, блок переноса (`accent-muted`) над шагами и подзаголовок «Затем установите приложение», шаги на подложке `secondary` с иконками-подсказками (`Share`, `SquarePlus`, `EllipsisVertical`, `Copy`), во встроенном браузере — адрес приложения и «Скопировать ссылку», иначе — «Понятно». Шире 1024 px — диалог 480 px.
- **Группа «Приложение»:** у значения иконка и цвет — `success` (`CircleCheck`, `ShieldCheck`), `warning` (`ShieldAlert`), `muted-foreground` (`Globe`, `AppWindow`). Действие — пилюля `secondary` с иконкой `accent`. На десктопе группа идёт на всю ширину сетки сразу после «Валюты». В скелетоне настроек — группа из двух строк.
- **Тосты:** успешные — 4 с (по умолчанию), ошибки «Браузер не разрешил защиту…» и «Не удалось скопировать ссылку» — 8 с. У ошибки копирования описание из адреса и подсказки «Нажмите на адрес и удерживайте, чтобы скопировать».
- Новые пары «текст / фон»: `success` и `warning` на `card` — добавить в `scripts/check-contrast.mjs`.

### 9. Манифест (`vite.config.ts`)

- **`id: base`.** Совпадает с текущим вычисленным id (= `start_url` = `base`), поэтому уже установленные копии остаются тем же приложением. Перед релизом сверяем «App Id» в DevTools → Application → Manifest до и после.
- **`description`** — текст из спеки.
- **Иконки:** к двум maskable добавляем `pwa-192x192.png` и `pwa-512x512.png` с `purpose: "any"`. Геометрия — по артборду `IconAny`: карточка 432 × 432 с отступом 40 px от краёв холста 512, рамка 22 px `#171A21`, радиус 116, белый фон, полосы 56 px — `owed-to-me` во всю ширину и `i-owe` на 60 %; углы прозрачные. Растр снимаем разовым Playwright-скриптом из scratchpad, PNG коммитим в `public/`.
- **`shortcuts`:** «Новый долг» → `${base}new`, «Разделить счёт» → `${base}bills/new`. Иконки 96 × 96 по артбордам `ShortcutIcon` / `ShortcutSplit`: квадрат `accent` с белым глифом Lucide (`ArrowLeftRight` / `Split`), `public/shortcut-new-debt.png` и `public/shortcut-split.png`. Маршруты уже открываются по прямой ссылке (`BrowserRouter basename`, `navigateFallback`).
- **`screenshots`:** в `public/screenshots/` три `form_factor: "narrow"` 1080×2340 (главная с итогами, карточка контакта, счёт) и один `"wide"` 1440×900 (главная). По артбордам `Shot*`: узкие — экран приложения в скруглённой рамке на фоне `#E9EBF0` с подписью сверху («Сколько должны вам и сколько должны вы», «Вся история с человеком на одном экране», «Общий счёт: кто кому сколько переводит»); широкий — экран без рамки. Экран снимаем из собранного приложения на демо-данных в светлой теме, рамку и подпись собираем там же: одноразовый Playwright-скрипт в scratchpad, Chromium уже есть в окружении. В precache не попадают: `workbox.globIgnores: ["**/screenshots/**"]`. Браузер загружает их только для диалога установки.

## Risks / Trade-offs

- [UA-регулярка не узнаёт встроенный браузер или ошибочно считает обычный браузер встроенным] → в первом случае пользователь видит общую инструкцию. Во втором регулярка узкая, и можно её поправить без изменения спеки.
- [Встроенные браузеры на iOS неотличимы от Safari (SFSafariViewController), и пункта «На экран «Домой»» там может не быть] → в шторке iOS есть подсказка «Если пункта … нет, откройте эту страницу в Safari».
- [`beforeinstallprompt` не придёт, если приложение уже установлено, но открыто во вкладке] → мягкая подсказка в шторке «Если приложение уже установлено, откройте его с экрана «Домой»».
- [Неверный `id` задвоит иконки у текущих пользователей] → `id` равен текущему `start_url`, сверка в DevTools до релиза.
- [Скриншоты устареют после редизайна] → в `docs/architecture.md` (раздел PWA) отметить, что их нужно переснимать при заметных изменениях главной.
- [Firefox в установленном режиме покажет диалог о хранилище при первом запуске] → принимаем: это осознанная установка, а защита данных — её цель.
- [Плашка разово появится у существующих пользователей с данными] → это желательно, особенно для пользователей Safari. Закрыть её — одно нажатие.

## Migration Plan

Формат базы и резервной копии не меняется. После выкладки:
1. Service worker обновляется по обычному тосту «Доступна новая версия».
2. Браузеры перечитывают манифест. Chrome на Android обновляет установленную копию (иконки, ярлыки) в фоне в течение нескольких дней.

Откат — revert коммита. Ключ `debts.installBannerDismissed` в `localStorage` безвреден и для старой версии.
