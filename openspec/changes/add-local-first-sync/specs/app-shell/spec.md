# Spec Delta

## MODIFIED Requirements

### Requirement: Основная навигация
Система SHALL предоставлять три раздела: «Главная» (`/`), «Контакты» (`/contacts`), «Настройки» (`/settings`). На ширине меньше 1024 px — плавающее полупрозрачное нижнее меню с иконками и подписями и круглая кнопка «+» справа; на большей — боковое меню с названием приложения и «+» справа внизу. Подпись SHALL соответствовать местному режиму либо местной копии с синхронизацией аккаунта. Неизвестный адрес перенаправляет на главную. При конфликте создание недоступно по `sync-conflicts`.

#### Scenario: Мобильная ширина
- **WHEN** ширина окна меньше 1024 px и открыт один из разделов
- **THEN** внизу видно плавающее меню из трёх разделов и кнопка «+», с учётом безопасной зоны в установленном приложении

#### Scenario: Десктоп
- **WHEN** ширина окна 1024 px и больше
- **THEN** слева боковое меню разделов, кнопка «+» — в правом нижнем углу

#### Scenario: Неизвестный адрес
- **WHEN** пользователь открывает несуществующий путь
- **THEN** приложение перенаправляет на главную

#### Scenario: Аккаунт подключён
- **WHEN** пользователь подключил синхронизацию
- **THEN** каркас больше не утверждает, что финансовые данные хранятся только на устройстве

### Requirement: Офлайн-работа (PWA)
Система SHALL после успешного кеширования работать без сети для просмотра и местного учёта долгов, счетов и контактов независимо от входа. Экспорт доступен без сети, импорт — только в локальном режиме. Известный конфликт блокирует обычную финансовую запись по `sync-conflicts`, но не просмотр и разбор. Вход и серверные действия требуют сети, их недоступность не блокирует запуск локальной реплики. Приложение устанавливается как PWA.

#### Scenario: Запуск без сети
- **WHEN** приложение уже открывалось ранее и сеть недоступна
- **THEN** приложение запускается из местного состояния без ожидания сервера; при отсутствии конфликтов доступен местный учёт

#### Scenario: Аккаунт без связи
- **WHEN** пользователь ранее вошёл, а сервер теперь недоступен
- **THEN** главная и карточки открываются из местной базы, финансовая запись не ждёт ответа сервера

## ADDED Requirements

### Requirement: Навигация аккаунта и расхождений
Система SHALL в серверной поставке предоставлять вход в раздел аккаунта и синхронизации из настроек и в «Расхождения» из настроек и предупреждения. Вложенные экраны на телефоне открываются без нижнего меню с понятным возвратом, на десктопе сохраняют каркас настроек. Локальная поставка не показывает недоступный вход.

#### Scenario: Переход из предупреждения
- **WHEN** пользователь нажимает «Разобрать расхождения» в баннере
- **THEN** открывается список конфликтов активного набора, а возврат ведёт на исходный экран

### Requirement: Гидрация без сетевого барьера
Система SHALL показывать скелетоны только на время местного чтения активного набора. Проверка сеанса, серверных возможностей и обмен SHALL NOT задерживать доступ к уже сохранённой реплике или подменять её гостевыми данными при сетевой ошибке.

#### Scenario: Медленный сервер
- **WHEN** местная база прочитана, но сервер не отвечает
- **THEN** сохранённые записи показаны, ожидание серверного ответа не удерживает скелетон
