# data-management Specification

## Purpose

Все данные хранятся только на устройстве пользователя. Capability описывает локальное хранение, резервное копирование в файл, восстановление из него и сброс данных.

## Requirements

### Requirement: Локальное хранение
Система SHALL хранить контакты, долги, операции и кэш курса только в локальной базе браузера (без сервера и аккаунта), а настройки интерфейса (тема, валюта отображения) — отдельно от доменных данных. Один профиль браузера — один пользователь.

#### Scenario: Перезапуск приложения
- **WHEN** пользователь закрывает и снова открывает приложение
- **THEN** все контакты, долги, история и настройки сохранены

### Requirement: Экспорт резервной копии
Система SHALL в настройках по кнопке «Экспортировать» сохранять файл `debts-backup-YYYY-MM-DD.json` со всеми контактами, долгами, операциями, служебными данными и датой экспорта, без обращения к сети.

#### Scenario: Успешный экспорт
- **WHEN** пользователь нажимает «Экспортировать»
- **THEN** скачивается JSON-файл и показывается уведомление «Резервная копия сохранена»

### Requirement: Импорт резервной копии
Система SHALL по кнопке «Импортировать» принимать JSON-файл резервной копии, проверять его формат и перед применением показывать подтверждение со сводкой (число контактов, число долгов, дата экспорта). После подтверждения текущие данные полностью заменяются содержимым файла и приложение перезагружается.

#### Scenario: Успешный импорт
- **WHEN** пользователь выбирает корректный файл и подтверждает импорт
- **THEN** данные заменяются, показывается «Данные успешно импортированы», страница перезагружается

#### Scenario: Неверный файл
- **WHEN** выбранный файл не является JSON или не похож на резервную копию
- **THEN** показывается уведомление об ошибке, текущие данные не изменяются

#### Scenario: Отмена импорта
- **WHEN** пользователь отменяет подтверждение импорта
- **THEN** текущие данные не изменяются

### Requirement: Сброс данных
Система SHALL в настройках в блоке «Данные и сброс» предлагать три действия, каждое — с подтверждением: «Удалить данные приложения» (все контакты, долги и история; страница перезагружается), «Сбросить настройки интерфейса» (тема и валюта отображения), «Очистить всё» (оба действия и перезагрузка).

#### Scenario: Удаление данных
- **WHEN** пользователь подтверждает «Удалить данные приложения»
- **THEN** все доменные данные удаляются, настройки интерфейса сохраняются, приложение перезагружается пустым

### Requirement: Ошибка чтения хранилища
Система SHALL при ошибке чтения локальной базы при запуске всё равно открыть интерфейс и показать баннер «Ошибка хранилища: …», чтобы пользователь мог воспользоваться сбросом данных в настройках.

#### Scenario: Повреждённая база
- **WHEN** чтение данных при запуске завершилось ошибкой
- **THEN** интерфейс открывается, показывается баннер ошибки хранилища
