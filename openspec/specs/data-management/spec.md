# data-management Specification

## Purpose

Все данные хранятся только на устройстве пользователя. Capability описывает локальное хранение, резервное копирование в файл, восстановление из него и сброс данных.

## Requirements

### Requirement: Локальное хранение
Система SHALL хранить контакты, долги, операции и кэш курса только в локальной базе браузера (без сервера и аккаунта), а настройки интерфейса (тема, валюта отображения) — отдельно от доменных данных. Один профиль браузера — один пользователь.

#### Scenario: Перезапуск приложения
- **WHEN** пользователь закрывает и снова открывает приложение
- **THEN** все контакты, долги, история и настройки сохранены

### Requirement: Экспорт резервной копии
Система SHALL в настройках в группе «Резервная копия» по кнопке «Сохранить в файл» сохранять файл `debts-backup-YYYY-MM-DD.json` со всеми контактами, долгами, операциями, служебными данными и датой экспорта, без обращения к сети. Под кнопками — пояснение «Файл JSON со всеми контактами, долгами и историей.»

#### Scenario: Успешный экспорт
- **WHEN** пользователь нажимает «Сохранить в файл»
- **THEN** скачивается JSON-файл и показывается тост «Резервная копия сохранена»

### Requirement: Импорт резервной копии
Система SHALL по кнопке «Загрузить из файла» (в настройках или «Восстановить из резервной копии» на пустой главной) принимать JSON-файл копии, проверять формат и показывать шторку «Загрузить резервную копию?» со строками «Контактов», «Долгов», «Копия создана» и текстом о замене данных. По «Заменить данные» данные полностью заменяются, приложение перезагружается.

#### Scenario: Успешный импорт
- **WHEN** пользователь выбирает корректный файл и подтверждает «Заменить данные»
- **THEN** данные заменяются, показывается тост «Данные успешно импортированы», страница перезагружается

#### Scenario: Сводка в подтверждении
- **WHEN** выбран файл с 5 контактами и 8 долгами, созданный 12 октября 2026 года в 18:05 по местному времени
- **THEN** шторка показывает «Контактов 5», «Долгов 8», «Копия создана 12 октября 2026, 18:05» и «Всё, что сейчас записано на этом устройстве, заменится данными из копии.»

#### Scenario: Неверный файл
- **WHEN** выбранный файл не является резервной копией
- **THEN** показывается тост «Не удалось импортировать: это не файл резервной копии», текущие данные не изменяются

#### Scenario: Отмена импорта
- **WHEN** пользователь нажимает «Отмена» в шторке подтверждения
- **THEN** текущие данные не изменяются

### Requirement: Сброс данных
Система SHALL в настройках в группе «Сброс» предлагать три действия с пояснениями, каждое — с подтверждением:
- «Удалить данные приложения» — «Контакты, долги и история. Настройки останутся.»;
- «Сбросить настройки интерфейса» — «Тема и валюта итогов. Долги не затрагиваются.»;
- «Очистить всё» — «Данные и настройки. Приложение перезагрузится.»

#### Scenario: Удаление данных
- **WHEN** пользователь подтверждает «Удалить данные приложения»
- **THEN** все доменные данные удаляются, настройки интерфейса сохраняются, приложение перезагружается пустым

### Requirement: Ошибка чтения хранилища
Система SHALL при ошибке чтения локальной базы при запуске всё равно открыть интерфейс и показать под заголовком экрана баннер «Ошибка хранилища: …» с кнопкой «Понятно», чтобы пользователь мог воспользоваться сбросом данных в настройках.

#### Scenario: Повреждённая база
- **WHEN** чтение данных при запуске завершилось ошибкой
- **THEN** интерфейс открывается, под заголовком показывается баннер ошибки хранилища
