# creation-drafts Specification

## Purpose

Сохранность незавершённого создания долга и счёта: пользователь продолжает ввод на том же устройстве после выхода из формы, перезапуска браузера или выгрузки установленного приложения из памяти.

## Requirements

### Requirement: Автоматическое сохранение незавершённого ввода
Система SHALL автоматически сохранять изменения формы создания на устройстве по мере ввода, без отдельной кнопки и без ожидания выхода из приложения. Неполные и не прошедшие проверку поля сохраняются. Одновременно существуют не более одного черновика долга и одного черновика счёта; они не заменяют друг друга.

#### Scenario: Выгрузка приложения
- **WHEN** пользователь частично заполнил форму, автосохранение завершилось, затем приложение выгружено из памяти и запущено заново без сети
- **THEN** сохранённый ввод доступен для продолжения

#### Scenario: Независимые формы
- **WHEN** пользователь начал долг, вышел из формы и начал счёт
- **THEN** оба черновика доступны независимо

#### Scenario: Открытие без изменений
- **WHEN** пользователь открыл новую форму и вышел, ничего не меняя
- **THEN** новый черновик не появляется, включая открытие долга с предвыбранным контактом

### Requirement: Полнота восстановления долга
Система SHALL восстанавливать выбранный контакт, направление, валюту, исходную строку суммы и заметку черновика долга. Открытие формы создания через любой вход продолжает существующий черновик, не перезаписывая его начальными значениями другого входа.

#### Scenario: Незавершённая сумма
- **WHEN** в черновике выбраны контакт, «Я должен», USD, введена заметка и не завершён ввод суммы
- **THEN** после повторного открытия формы все значения восстановлены без требования сначала исправить сумму

#### Scenario: Вход с другим контактом
- **WHEN** существует черновик для Анны, а пользователь открывает создание долга из карточки Ивана
- **THEN** открывается черновик с Анной, введённые значения не заменяются

### Requirement: Полнота восстановления счёта
Система SHALL восстанавливать режим ввода и все данные формы счёта: сумму, валюту, описание, порядок участников, плательщиков, оплаты, способ деления, доли и суммы, позиции с отметками и людьми без имени, скидку и чаевые. Сохраняются незавершённые строки и данные временно скрытого режима. В режиме «Одной суммой» восстанавливается текущий шаг.

#### Scenario: Незавершённая позиция чека
- **WHEN** у позиции заполнено только название, у другой — цена без отметок, а скидка содержит недопустимое значение
- **THEN** после перезапуска восстановлены обе позиции и введённая скидка; их ошибки не мешают восстановлению

#### Scenario: Второй шаг
- **WHEN** пользователь на втором шаге счёта «Одной суммой» распределил только часть суммы и перезапустил приложение
- **THEN** продолжение открывает второй шаг с исходными оплатами, способом деления и распределёнными суммами

#### Scenario: Переключение режимов
- **WHEN** пользователь заполнил позиции чека, переключился на «Одной суммой» и перезапустил приложение
- **THEN** восстановлен режим «Одной суммой», а при переключении на «По чеку» сохранённые позиции доступны

### Requirement: Выход с сохранением и удаление черновика
Система SHALL сохранять черновик при выходе через «Назад» или навигацию браузера. «Удалить черновик» доступно отдельно на форме и главной и требует подтверждения «Удалить черновик?» с текстом «Введённые данные удалятся» и кнопками «Удалить черновик» / «Продолжить заполнение». Неоднозначная кнопка «Отмена» в этих действиях не используется.

#### Scenario: Выход из формы
- **WHEN** пользователь нажимает «Назад» на форме долга или первом шаге счёта
- **THEN** открывается экран, откуда пришёл пользователь, а черновик остаётся доступным

#### Scenario: Выход при ошибке автосохранения
- **WHEN** пользователь нажимает «Назад», а запись последних изменений завершилась ошибкой
- **THEN** показывается подтверждение «Выйти без сохранения последних изменений?» с текстом «Не удалось сохранить черновик. Последние изменения могут потеряться после закрытия приложения.» и кнопками «Остаться» / «Выйти»
- **AND** «Остаться» или закрытие подтверждения оставляет форму открытой; «Выйти» возвращает на предыдущий экран без удаления актуального ввода из памяти и прежнего сохранённого черновика

#### Scenario: Удаление подтверждено
- **WHEN** пользователь подтверждает удаление черновика на форме
- **THEN** удаляется только этот черновик, форма закрывается, её пустое состояние не создаёт новый черновик

#### Scenario: Продолжение вместо удаления
- **WHEN** пользователь нажимает «Продолжить заполнение» или закрывает подтверждение без удаления
- **THEN** черновик не меняется, пользователь остаётся там, где открыл подтверждение

### Requirement: Черновики не являются финансовыми записями
Система SHALL создавать долг, счёт и операции только после явного успешного завершения формы. Черновики не входят в суммы, остатки, списки долгов, счётчики счетов и историю. Успешное создание записи удаляет соответствующий черновик как единое действие; ошибка сохраняет его для повторной попытки.

#### Scenario: Заполнено без создания
- **WHEN** пользователь ввёл валидный счёт и вышел, не нажав «Сохранить счёт»
- **THEN** счёт и долги не появляются, итоги не меняются, черновик доступен

#### Scenario: Успешное создание
- **WHEN** долг или счёт успешно создан и приложение сразу перезапущено
- **THEN** видна созданная запись, соответствующий черновик отсутствует, черновик другого вида сохранён

#### Scenario: Ошибка окончательной записи
- **WHEN** создание долга или счёта не удалось
- **THEN** форма и черновик остаются, частичная запись не появляется

### Requirement: Ошибки автосохранения
Система SHALL при ошибке записи черновика сохранять текущий ввод в открытой форме и показывать «Не удалось сохранить черновик. Последние изменения могут потеряться после закрытия приложения.» с действием «Повторить». Подтверждение сохранения показывается только после успешной записи; прежняя сохранённая версия не заменяется пустой формой при ошибке чтения.

#### Scenario: Ошибка записи и повтор
- **WHEN** автосохранение завершилось ошибкой и пользователь нажал «Повторить» после устранения причины
- **THEN** повторно сохраняется актуальный ввод, после успеха предупреждение исчезает

#### Scenario: Ошибка чтения
- **WHEN** черновик не удалось прочитать при открытии формы
- **THEN** показана ошибка с действием «Повторить», сохранённый черновик не перезаписывается начальными значениями

#### Scenario: Повреждённый черновик
- **WHEN** сохранённый черновик имеет неизвестную версию или повреждённую структуру
- **THEN** форма не открывается с начальными значениями; показана ошибка восстановления с «Повторить», «Удалить черновик» и «Назад»
- **AND** удаление требует обычного подтверждения, после успеха пользователь выходит из формы и может начать создание заново

#### Scenario: Ошибка удаления
- **WHEN** удаление черновика завершилось ошибкой
- **THEN** черновик остаётся доступным, показано «Не удалось удалить черновик. Попробуйте ещё раз.»
