# Долги — инструкции для агентов

Offline-first PWA для учёта личных долгов. Интерфейс и документация — на русском.

Этот файл — единая входная точка инструкций для агентов в репозитории. Применяй правила ниже без отдельного напоминания пользователя.

## Перед изменением кода

Перед проектированием изменения прочитай:

- [Архитектуру](docs/architecture.md) — устройство кода и слои FSD.
- [Предметную область](docs/domain.md) — термины и модель данных.
- [Правила кода](docs/coding-standards.md) — FSD, TypeScript, i18n, модалки, shadcn и стили.
- [Бриф на редизайн](docs/design-brief.md) — требования к интерфейсу.
- [Бэклог](docs/roadmap.md) — контекст запланированных изменений.

Для изменений интерфейса дополнительно прочитай [дизайн-систему](docs/design-system.md).

## Поведение продукта и OpenSpec

- Источник истины о поведении продукта — [спецификации](openspec/specs/) (`<capability>/spec.md`). Перед правкой прочитай спецификации затронутых возможностей и проверь [активные изменения](openspec/changes/).
- Новая функциональность и изменения наблюдаемого поведения ведутся через OpenSpec: предложение → ревью → реализация → архивирование. Соответствующие команды в клиентах, где они доступны: `/opsx:propose` → `/opsx:apply` → `/opsx:archive`.
- Мелкие исправления ошибок, включая исправления взаимодействия с интерфейсом без новых пользовательских сценариев, можно выполнять без OpenSpec change. Пользовательские исправления всё равно фиксируй в changelog.
- Соблюдай [контекст и правила OpenSpec](openspec/config.yaml). Артефакты пиши на русском, сохраняя структурные заголовки OpenSpec и ключевые слова SHALL/MUST на английском.

## Сопутствующая документация

- Пользовательские изменения фиксируй в [CHANGELOG.md](CHANGELOG.md), раздел `[Unreleased]`, в том же изменении и коммите, что и код.
- Если меняются структура кода или модель данных, обновляй [архитектуру](docs/architecture.md) и/или [предметную область](docs/domain.md).

## Проверки

Перед коммитом выполни все команды:

```sh
npm run check
npm run knip
npm run spec:validate
npm run build
```

Если проверку невозможно выполнить, явно укажи в результате, какая проверка не запущена и почему. Не считай её пройденной.
